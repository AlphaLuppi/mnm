## Description

The plugin import endpoint (`POST /companies/:companyId/governed-workflows/import-plugin`) accepts `repo_url` from the request body:

```typescript
// governed-workflows-ui.ts:617-637
const { repo_url, ref, exclude_skills, exclude_agents } = (req.body ?? {}) as {
  repo_url?: string; ...
};
if (!repo_url || typeof repo_url !== "string") {
  return apiError(res, 400, "IMPORT_VALIDATION", "repo_url required", [...]);
}
// No URL validation beyond the string check above
const sourceProvider = await buildSourceProvider({ db, companyId, url: repo_url, userId });
```

The `repo_url` is passed directly to `buildSourceProvider` which resolves a git provider. Depending on the git provider implementation, this could:
1. Trigger an HTTP(S) fetch to a user-controlled URL.
2. Accept `file://` scheme (if the git implementation supports it) — local file read.
3. Accept internal git endpoints like `http://internal-git-server/`.

Requires `WORKFLOWS_CREATE` permission (authenticated, company-scoped) so the attack surface is limited to privileged users — but a compromised or malicious user with this permission could use it to probe internal git services.

Additionally, the `ref` parameter (git branch/tag/SHA) is passed without length or character validation.

## Impact

- SSRF via HTTP(S) git clone to internal endpoints.
- Potential local file read via `file://` scheme (depends on git provider implementation).
- Limited to `WORKFLOWS_CREATE` permission holders.

## Recommendation

1. Validate `repo_url` with an allowlist: `https://` only, block private IPs (reuse the SSRF guard from SEC-T5-002).
2. Validate `ref`: `z.string().max(200).regex(/^[A-Za-z0-9/_.-]+$/).optional()`.
3. Log all plugin import operations with the `repo_url` for audit trail.
