## Description

All upload endpoints store `file.originalname` (from multer, sourced from the multipart `filename` parameter) without sanitization:

```typescript
// documents.ts:76-82
const stored = await storage.putFile({
  ...
  originalFilename: file.originalname || null,  // attacker-controlled
  ...
});
```

The filename is:
1. Stored in the `assets.original_filename` DB column.
2. Reflected in `Content-Disposition: attachment; filename="..."` HTTP headers on the download endpoint:
```typescript
// documents.ts:208-209
const filename = doc.title || asset.originalFilename || "document";
res.setHeader("Content-Disposition", `attachment; filename="${filename.replaceAll('"', '')}"`);
```
3. Used in `putFile` → `localDiskProvider` → stored as an object key (though `normalizeObjectKey` in local-disk-provider.ts correctly rejects `..` segments — this is properly defended).

The `Content-Disposition` sanitization removes only double-quotes. It does not handle:
- Newline injection (`\r\n`) which could split HTTP response headers (CWE-113 HTTP Response Splitting).
- NUL byte injection (rare but possible in some header parsers).
- Unicode normalization attacks that render differently in browsers.
- Filenames over 255 bytes which may cause issues in some filesystems.

Additionally, `assets.ts:152` has the same pattern:
```typescript
res.setHeader("Content-Disposition", `inline; filename=\"${filename.replaceAll("\"", "")}\"`);
```

## Impact

- Header injection via newline in filename (low risk with modern HTTP/1.1 parsers, but not zero).
- Stored malicious filenames in the DB that could confuse audit logs or downstream processors.
- Filenames with special characters may behave unexpectedly on Windows filesystems (local storage).

## Reproduction

```bash
curl -X POST ".../documents/upload" \
  -F $'file=@test.txt;filename="malicious\r\nX-Injected: header"'
```

## Recommendation

Sanitize `originalFilename` before storing and before reflecting in headers:
```typescript
function sanitizeFilename(name: string): string {
  return name
    .replace(/[\\/:*?"<>|]/g, '_')  // Windows-unsafe chars
    .replace(/[\r\n\0]/g, '')        // Header-injection chars
    .replace(/\.{2,}/g, '.')         // Double dots
    .trim()
    .slice(0, 255);                  // Length limit
}
```
Use `encodeURIComponent` or RFC 5987 encoding for `Content-Disposition filename*=` in headers.
