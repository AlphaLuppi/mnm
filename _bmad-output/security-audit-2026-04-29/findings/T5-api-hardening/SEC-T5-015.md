## Description

The AI chat endpoint (`POST /companies/:companyId/governed-workflows/:name/ai/chat`) has input validation:

```typescript
const bodySchema = z.object({
  messages: z.array(z.object({
    role: z.enum(["user", "assistant"]),
    content: z.string().min(1).max(10_000),
  })).min(1).max(50),
  ref: z.string().optional(),
});
```

This is correctly validated. However:

1. **`ref` field has no max length or character restriction** — `z.string().optional()` accepts any string. A very long `ref` (e.g. 100,000 chars) is passed to the git provider without length capping.

2. **Concurrency limiter is in-memory, per-factory**: `createConcurrencyCounter(3)` is instantiated once per `governedWorkflowsAiRoutes()` factory call. If the server uses multiple instances (horizontal scaling without Redis), each instance has its own counter. An actor can maintain 3×N concurrent SSE streams with N instances.

3. **No global rate limit on AI endpoint** distinct from the general API rate limiter (500 req/min total across all routes). A single actor could dedicate all 500 req/min to the AI endpoint, each initiating a 60-second Anthropic API call.

4. **SSE connection cleanup on `aborted` event**: The code notes that `close` fires after request body consumption on Node 18+, so it listens to `aborted`. This is correct, but `aborted` is deprecated in Node 18 and removed in Node 19+. In newer Node versions, the abort signal may not fire, causing the concurrency counter to not be released, eventually blocking all 3 slots permanently.

## Impact

- Low: `ref` accepts unbounded input to git provider.
- Low: SSE concurrency leaks in newer Node versions could exhaust the 3-slot limit permanently.
- Info: Multi-instance bypass of concurrency limit.

## Recommendation

1. Add `z.string().max(200).regex(/^[A-Za-z0-9/_.-]*$/).optional()` for the `ref` field.
2. Replace `req.on('aborted', ...)` with `req.on('close', ...)` and check `req.destroyed` — this works reliably in all Node 18+ versions.
3. Consider using a Redis-backed semaphore for concurrency control in multi-instance deployments.
