## Description

The document upload endpoint and folder upload endpoint (`POST /companies/:companyId/documents/upload` and `POST /companies/:companyId/folders/:id/upload`) use multer with a size limit but **no MIME type allowlist**:

```typescript
// documents.ts:17,24-27
const MAX_DOCUMENT_BYTES = ... || 50 * 1024 * 1024;
const upload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: MAX_DOCUMENT_BYTES, files: 1 },
  // No fileFilter — all MIME types accepted
});
```

The issue asset endpoint DOES restrict MIME types:
```typescript
// issues.ts:35-41 — correct
const ALLOWED_ATTACHMENT_CONTENT_TYPES = new Set(["image/png", "image/jpeg", ...]);
```

The document and folder upload routes do not. The `mimeType` field is taken directly from `file.mimetype` (which comes from the multipart Content-Type header, attacker-controlled) with no independent server-side verification:

```typescript
// documents.ts:70-71
const mimeType = file.mimetype || "application/octet-stream";
```

As a result:
1. An attacker can upload an executable (`.exe`, `.sh`, `.js`) with a benign MIME type.
2. An SVG file (which can contain `<script>`) can be uploaded and potentially served with `Content-Type: image/svg+xml`, leading to XSS if served inline.
3. Files containing polyglot payloads (JPEG+ZIP, PNG+PHP, etc.) bypass the MIME check by using a legitimate MIME type.
4. The `originalFilename` from multer comes from the multipart headers and is not sanitized before storage — see SEC-T5-008.

The 50 MB limit for documents is also very generous for a document management system.

## Impact

- Malicious files stored in the company's storage that can be delivered to other users.
- SVG-based XSS if files are served inline.
- Possible exploitation by downstream document processing pipeline (ingestion, LLM summarization).

## Reproduction

```bash
# Upload an SVG with script content
curl -X POST "http://localhost:3100/api/companies/COMPANY_ID/documents/upload" \
  -F "file=@evil.svg;type=image/svg+xml" \
  -H "Authorization: Bearer TOKEN"
# Then GET /documents/:id/content — browser renders SVG with script
```

## Recommendation

1. Define a strict allowlist of accepted MIME types for document uploads (PDF, DOCX, TXT, MD, CSV, XLSX).
2. Validate the file magic bytes independently from the `mimetype` header:
```typescript
import fileType from 'file-type';
const detected = await fileType.fromBuffer(file.buffer);
if (!ALLOWED_MAGIC_TYPES.has(detected?.mime)) { ... }
```
3. Always serve uploaded files with `Content-Disposition: attachment` (not `inline`) to prevent in-browser rendering.
4. Reduce the document upload limit from 50 MB to something more realistic for text documents.
