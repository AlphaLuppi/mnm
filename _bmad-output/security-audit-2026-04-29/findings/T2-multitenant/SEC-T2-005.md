## Description

The HTTP-to-WebSocket upgrade handler for `/api/companies/:companyId/events/ws` extracts the company ID from the URL path using:

```typescript
function parseCompanyId(pathname: string) {
  const match = pathname.match(/^\/api\/companies\/([^/]+)\/events\/ws$/);
  if (!match) return null;
  try {
    return decodeURIComponent(match[1] ?? "");
  } catch {
    return null;
  }
}
```

Unlike the HTTP middleware chain (`assertCompanyMembership` which validates UUID format with `UUID_RE`), this WS path extraction **does not validate that the extracted companyId is a valid UUID**. 

Any non-UUID string (e.g., `../../../etc/passwd`, `'; DROP TABLE agents; --`, or `x`) passes the regex and is sent to `authorizeUpgrade` → then to `subscribeCompanyLiveEvents(ctx.companyId, ...)`.

The `tenantContextMiddleware` is NOT involved in WS upgrades (it's an HTTP middleware, WS upgrades bypass it). The `authorizeUpgrade` function does perform company membership checks but only after accepting the malformed companyId.

Additionally, if `authorizeUpgrade` succeeds with a malformed companyId (e.g. an attacker finds a membership row with a non-UUID companyId somehow), `subscribeCompanyLiveEvents` is called with an arbitrary string as the subscription key.

## Impact

**HIGH.** While the membership check in `authorizeUpgrade` queries the DB (which should fail for non-UUID values due to type coercion), this creates an inconsistency with the HTTP path which explicitly rejects non-UUID company IDs at the middleware level. The lack of early validation allows:
1. Unexpected error messages that could information-disclose internal stack traces
2. A future code path or migration that registers a non-UUID as a companyId could be exploited

Furthermore, the WebSocket route bypasses the HTTP middleware chain entirely, meaning it lacks the following guards present in the HTTP path:
- UUID format validation
- `boardMutationGuard`
- HTTP rate limiting (the WS has no rate limiter after upgrade)

## Reproduction

```
ws://server/api/companies/NOT-A-UUID/events/ws
```

## Recommendation

Add UUID validation immediately after extraction in `parseCompanyId`:

```typescript
const UUID_RE = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

function parseCompanyId(pathname: string): string | null {
  const match = pathname.match(/^\/api\/companies\/([^/]+)\/events\/ws$/);
  if (!match) return null;
  try {
    const companyId = decodeURIComponent(match[1] ?? "");
    if (!UUID_RE.test(companyId)) return null; // reject non-UUID
    return companyId;
  } catch {
    return null;
  }
}
```

Also consider rate-limiting WS upgrade attempts (e.g., max 10 per IP per minute).
