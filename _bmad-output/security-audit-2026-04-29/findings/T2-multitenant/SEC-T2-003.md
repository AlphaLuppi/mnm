## Description

The deployment preview proxy middleware (`/preview/:deploymentId/*`) performs auth check using only:
```typescript
const hasSession = !!(req as any).actor;
const hasValidToken = shareTokenParam && shareTokenParam === info.shareToken;

if (!hasSession && !hasValidToken) {
  res.status(401).json({ error: "Authentication required." });
  return;
}
```

The check is: **is the actor authenticated at all?** — not: **does the actor belong to the company that owns this deployment?**

A user authenticated to Company A can access the preview deployment of Company B by simply hitting `/preview/<company-B-deployment-id>`.

This is a pure IDOR (Insecure Direct Object Reference). The `info` object retrieved from the DB cache contains `companyId` but that value is **never compared against the actor's company membership**.

The deployment ID is a UUID, so brute-force is hard, but:
1. If a deployment ID leaks via logs, error messages, or referrer headers, cross-company access is trivial
2. In authenticated deployments, share tokens can be guessed or leaked
3. The `portCache` stores `companyId` alongside `shareToken` — this data exists but is ignored for auth

## Impact

**CRITICAL.** Any authenticated MnM user can access live deployment previews belonging to any other company. Depending on the deployed artifact, this could expose:
- Proprietary agent-generated web applications
- Internal tooling with sensitive data
- The user's session tokens (the proxy forwards all headers including cookies)

## Reproduction

1. As attacker in Company A, enumerate or discover a deployment ID from Company B (e.g. via a shared link, log exposure, timing side-channel).
2. GET `/preview/<company-B-deployment-id>/` — this returns the Company B deployment content.

## Recommendation

After the DB lookup, verify the actor belongs to the deployment's company:

```typescript
// After fetching info from DB:
const actorCompanyIds = (req as any).actor?.companyIds ?? 
  ((req as any).actor?.companyId ? [(req as any).actor.companyId] : []);

if (!hasValidToken && !actorCompanyIds.includes(info.companyId)) {
  res.status(403).json({ error: "Access denied" });
  return;
}
```

Also: the `portCache` should be invalidated when deployment status changes. Currently, a revoked deployment could still be accessible for up to 60 seconds.
