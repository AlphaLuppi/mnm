## Description

The `agentService.getById()` function fetches agents by ID with NO company_id filter:

```typescript
async function getById(id: string) {
  const row = await db
    .select()
    .from(agents)
    .where(eq(agents.id, id))  // NO company_id filter
    .then((rows) => rows[0] ?? null);
  return row ? normalizeAgentRow(row) : null;
}
```

This function is called in 20+ places across routes and services. The application relies entirely on:
1. RLS being set correctly (which depends on `tenantContextMiddleware` having run)
2. The caller manually checking `agent.companyId` after the fetch

In HTTP request handlers, RLS is typically set before the query. But in background/async flows:
- `setTenantContext` must be manually called before any DB query
- If a background task calls `getById` without first setting the tenant context, RLS will filter by the **empty** `app.current_company_id` → returns null

More concerning: if RLS returns null and the caller does `if (!agent) return 404`, a legitimate agent could become invisible in background flows. This is a data integrity issue, not just a security one.

The `getById` function is also called in `actorMiddleware` itself (line 97-98 for agent JWT verification):
```typescript
const agentRecord = await db.select().from(agents).where(eq(agents.id, claims.sub))...
```
This runs BEFORE any company context is set, so RLS would block it if `app.current_company_id` is set from a previous request on the same connection.

## Impact

**MEDIUM.** The absence of explicit company_id filtering in `getById`:
1. Creates a dependency on RLS being correctly set — any break in that chain silently fails (returns null) rather than raising an error
2. In the auth middleware itself (JWT verification), the query runs without tenant context, meaning it could be affected by pool connection state from previous requests
3. Makes the code hard to reason about — callers must know to check `agent.companyId` post-fetch

## Recommendation

Add explicit company_id filtering to `getById` — or better, create a separate `getByIdForCompany(id, companyId)` function used by route handlers:

```typescript
async function getByIdForCompany(id: string, companyId: string) {
  const row = await db
    .select()
    .from(agents)
    .where(and(eq(agents.id, id), eq(agents.companyId, companyId)))
    .then((rows) => rows[0] ?? null);
  return row ? normalizeAgentRow(row) : null;
}
```

For auth middleware (JWT verification), the query should bypass RLS via a dedicated non-pooled connection or superuser context, or explicitly include company_id from claims:
```typescript
.where(and(eq(agents.id, claims.sub), eq(agents.companyId, claims.company_id)))
```
