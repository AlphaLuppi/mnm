## Description

In `local_trusted` deployment mode, `actorMiddleware` sets:

```typescript
req.actor = opts.deploymentMode === "local_trusted"
  ? { type: "board", userId: "local-board", isInstanceAdmin: true, source: "local_implicit" }
  : { type: "none", source: "none" };
```

The `assertCompanyMembership` middleware then bypasses ALL company membership checks for this actor:

```typescript
if (req.actor.type === "board") {
  // Dev mode — single-tenant trusted, skip check
  if (req.actor.source === "local_implicit" || req.actor.isInstanceAdmin) {
    next();  // <-- bypass all checks
    return;
  }
}
```

Similarly, `requirePermission` bypasses permission checks:
```typescript
if (req.actor.type === "board" && req.actor.source === "local_implicit") {
  next();
  return;
}
```

And `tagScopeMiddleware` grants `bypassTagFilter: true`.

**In `local_trusted` mode, there is literally no company isolation.** Any request to any `/companies/:companyId/...` endpoint with no authentication will succeed and see all data.

While `local_trusted` is documented as "dev mode", the security concern is:
1. If `local_trusted` is accidentally deployed to production (misconfiguration), ALL multi-tenant isolation is gone
2. There is no warning or safeguard that prevents `local_trusted` from being used in a multi-tenant scenario
3. The mode is controlled by `DEPLOYMENT_MODE` env var — if this env var is missing or defaults to `local_trusted`, production becomes insecure

## Impact

**HIGH.** Complete multi-tenant isolation bypass if `local_trusted` mode is active. In production SaaS, this would expose all companies' data to any unauthenticated request.

The risk is a deployment/configuration error, not a code logic error. But the consequence is catastrophic.

## Reproduction

1. Set `DEPLOYMENT_MODE=local_trusted` (or leave unset if default is `local_trusted`)
2. Send: `GET /api/companies/<any-company-id>/agents` with no auth header
3. Receive full agent list for that company

## Recommendation

1. Add a startup guard that prevents `local_trusted` mode when environment indicators suggest production:
   ```typescript
   if (opts.deploymentMode === "local_trusted" && process.env.NODE_ENV === "production") {
     throw new Error("FATAL: local_trusted mode is not allowed in production");
   }
   ```

2. Log a prominent WARNING at startup when `local_trusted` is active:
   ```
   ⚠️  WARNING: Running in local_trusted mode — multi-tenant isolation is DISABLED
   ```

3. Require an explicit opt-in env var (e.g., `MNM_LOCAL_TRUSTED=true`) that defaults to `false`; never use this as the default mode.
