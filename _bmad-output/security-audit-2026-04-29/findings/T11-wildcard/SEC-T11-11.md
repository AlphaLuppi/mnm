## Description

The agent JWT authentication uses a well-known fallback secret in `local_trusted` mode:

```typescript
// agent-auth-jwt.ts ~line 36-42
const rawSecret = process.env.MNM_AGENT_JWT_SECRET;
const secret = rawSecret || (deploymentMode === "local_trusted" ? "mnm-dev-secret" : null);
```

The string `"mnm-dev-secret"` is hardcoded in the source code, meaning it is:
1. Public knowledge (visible in this repo).
2. Present in any deployed instance running in `local_trusted` mode without explicitly setting `MNM_AGENT_JWT_SECRET`.

An attacker with local network access to a `local_trusted` instance can forge agent JWTs for any `agentId` and `companyId`, impersonating any agent.

This is expected behavior for a dev mode, BUT the risk is that:
- Production-like environments may run in `local_trusted` mode for convenience (e.g., small teams, internal tools).
- The well-known secret makes the "I'm running in dev" fact publicly documented and exploitable.

The token is valid for `MNM_AGENT_JWT_TTL_SECONDS` (default: 7200 seconds / 2 hours), giving a long window.

## Impact

- In `local_trusted` mode: full agent impersonation. An attacker can forge JWTs for any `agentId` with any `company_id`, bypassing all agent-level access control.
- In `authenticated` mode: no impact (secret must be explicitly set).
- Risk classification: low because `local_trusted` is dev-only by design, but the hardcoded string elevates the risk for misconfigured deployments.

## Reproduction (creative PoC)

```javascript
const crypto = require('crypto');
const secret = "mnm-dev-secret";  // public knowledge

function b64url(s) { return Buffer.from(s).toString('base64url'); }
const header = b64url(JSON.stringify({alg:"HS256",typ:"JWT"}));
const payload = b64url(JSON.stringify({
  sub: "any-agent-id", company_id: "any-company-id",
  adapter_type: "process", run_id: crypto.randomUUID(),
  iat: Math.floor(Date.now()/1000),
  exp: Math.floor(Date.now()/1000) + 7200
}));
const sig = crypto.createHmac('sha256', secret).update(`${header}.${payload}`).digest('base64url');
const token = `${header}.${payload}.${sig}`;
// Use as: MNM_API_KEY=<token>
```

## Recommendation

1. In `local_trusted` mode, generate a random secret at first startup and persist it to a local file (e.g., `.mnm/dev-jwt-secret`), rather than using a hardcoded string.
2. Log a clear warning if `MNM_AGENT_JWT_SECRET` is not set and the fallback is used: "WARNING: Using default dev JWT secret. Set MNM_AGENT_JWT_SECRET for production use."
3. Consider refusing to start in `local_trusted` mode if `NODE_ENV=production`.
