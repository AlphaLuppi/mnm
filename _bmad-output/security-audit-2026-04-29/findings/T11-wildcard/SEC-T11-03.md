## Description

`POST /api/companies/:companyId/roles` (requires `ROLES_MANAGE`) does check that an actor cannot create a role **above** their hierarchy level. However, it does **not** check whether the actor is allowed to set `bypassTagFilter: true` on the new role.

```typescript
// roles.ts ~line 104
if (actorRole && !actorRole.bypassTagFilter) {
  const targetLevel = hierarchyLevel ?? 100;
  if (targetLevel < actorRole.hierarchyLevel) {
    throw forbidden("Cannot create a role above your own hierarchy level");
  }
}
// No check: bypassTagFilter: true is accepted from any actor with ROLES_MANAGE
```

`bypassTagFilter: true` is the architectural equivalent of "admin-level tag visibility" — it bypasses the entire tag-based isolation system. This flag should only be settable by actors who themselves already have `bypassTagFilter`.

Additionally, `PATCH /api/roles/:roleId` (also requires `ROLES_MANAGE`) accepts `bypassTagFilter` in the update set with no guard:
```typescript
if (bypassTagFilter !== undefined) updates.bypassTagFilter = bypassTagFilter;
```

This means any user with `ROLES_MANAGE` at any hierarchy level can:
1. Create/modify a role with `bypassTagFilter: true`
2. Assign that role to themselves via `PATCH /members/:memberId/role` (requires `USERS_MANAGE`)
3. Gain full cross-tag visibility for all agents, issues, traces, and config layers

If the same user has both `ROLES_MANAGE` and `USERS_MANAGE` (a common admin bundle), this is a 2-step self-escalation.

## Impact

- Cross-tenant tag visibility bypass: the attacker can see all agents, issues, and traces belonging to tags they don't share with.
- In multi-team deployments, this defeats the entire organizational isolation model.
- The attack is silent — no audit event specifically tracks `bypassTagFilter` changes (the audit only logs `role.created` / `role.updated` with generic metadata).

## Reproduction (creative PoC)

```bash
# Assume actor has ROLES_MANAGE + USERS_MANAGE (standard manager bundle)

# Step 1: Create a spy role at same hierarchy level but with bypassTagFilter
POST /api/companies/{cid}/roles
{
  "name": "spy-role", "slug": "spy-role",
  "hierarchyLevel": 100,
  "bypassTagFilter": true
}
→ roleId = "spy-role-id"

# Step 2: Assign it to self
PATCH /api/companies/{cid}/members/{myMemberId}/role
{ "roleId": "spy-role-id" }

# Now actor sees all cross-tag data
GET /api/companies/{cid}/agents  # returns ALL agents in company
GET /api/companies/{cid}/issues  # returns ALL issues
```

## Recommendation

Add a guard in both `POST /roles` and `PATCH /roles/:roleId`:
```typescript
// Only actors whose current role already has bypassTagFilter, or instance admins,
// can create/update roles with bypassTagFilter: true
if (bypassTagFilter === true) {
  if (req.actor.type === "board" && req.actor.userId) {
    const actorRole = await access.resolveRole(companyId, "user", req.actor.userId);
    if (!actorRole?.bypassTagFilter && !req.actor.isInstanceAdmin) {
      throw forbidden("Cannot grant bypass_tag_filter — requires admin-level role");
    }
  }
}
```
