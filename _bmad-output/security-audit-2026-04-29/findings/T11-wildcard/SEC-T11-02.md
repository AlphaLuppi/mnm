## Description

The `POST /api/companies/import/preview` and `POST /api/companies/import` endpoints accept a `source` body field with `type: "url"` (or `type: "github"`). When `type="url"`, the server calls `fetchJson(source.url)` and then `fetchText(new URL(relativeFile, base).toString())` on every agent file path declared in the manifest — all with no validation that the URL does not point to an internal/private address.

```typescript
// company-portability.ts ~line 491
if (source.type === "url") {
  const manifestJson = await fetchJson(source.url);          // 1st outgoing request
  const base = new URL(".", source.url);
  for (const agent of manifest.agents) {
    const filePath = ensureMarkdownPath(agent.path);
    files[filePath] = await fetchText(new URL(filePath, base).toString()); // N more requests
  }
}
```

The `private-hostname-guard` middleware (`server/src/middleware/private-hostname-guard.ts`) protects **inbound** requests by checking the Host header. It has **no effect** on **outbound** `fetch()` calls made by the server itself.

Authorization: When `target.mode === "existing_company"`, only `assertCompanyAccess` is checked — no dedicated permission (no `COMPANY_IMPORT` permission requirement). Any authenticated member of the company can trigger this.

## Impact

- **SSRF to internal services**: An attacker who is a member of any company can make the MnM server fetch arbitrary URLs including `http://169.254.169.254/latest/meta-data/` (AWS IMDS), `http://localhost:PORT/internal-api`, or any internal microservice.
- **Amplification**: The manifest can list up to N agent files, each triggering a separate outgoing request to attacker-controlled or internal URLs — amplification factor limited only by manifest size.
- **Data exfiltration**: The response content (even from internal endpoints) is returned in the API response as file content, allowing the attacker to read the response.
- **`type: "github"` is less severe** — `parseGitHubTreeUrl` partially constrains the URL to `raw.githubusercontent.com` patterns, but `type: "url"` is completely open.

## Reproduction (creative PoC)

```bash
# Attacker is a member of company CUID
POST /api/companies/import/preview
{
  "source": {
    "type": "url",
    "url": "http://169.254.169.254/latest/meta-data/iam/security-credentials/role-name"
  },
  "target": { "mode": "existing_company", "companyId": "CUID" },
  "include": {}
}
# The server fetches the URL and returns the response (or an error revealing the content).
# For file-by-file exfil: craft a valid mnm.manifest.json at attacker.com that lists
# agent paths resolving to http://169.254.169.254/... sub-resources.
```

## Recommendation

1. **Validate outbound URLs** before `fetchJson`/`fetchText`: reject private/loopback/link-local addresses using a DNS + IP resolution check.
2. **Add a dedicated `COMPANY_IMPORT` permission** and require it for the `existing_company` path (currently only `assertCompanyAccess`).
3. Consider **allowlisting** URL schemes and hostnames (e.g., only `github.com`, `raw.githubusercontent.com`).
4. Use a separate sandboxed network namespace or outbound proxy for portability fetches.
