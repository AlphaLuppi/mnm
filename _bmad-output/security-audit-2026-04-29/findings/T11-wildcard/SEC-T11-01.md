## Description

The `PATCH /api/companies/:companyId/agents/:id` endpoint accepts `metadata` as a free-form `z.record(z.unknown())` field in `updateAgentSchema`. The handler copies `req.body` directly into `patchData` and passes it straight to `svc.update(id, patchData, ...)`. There is **no stripping of the `isCAO` key** from the metadata object before the DB write.

```typescript
// routes/agents.ts ~line 1103
const patchData = { ...(req.body as Record<string, unknown>) };
// ... various adapterConfig and adapterType checks ...
const agent = await svc.update(id, patchData, {...});
```

The `tag-filter.ts` service uses `metadata.isCAO === true && a.adapterType === "claude_local"` to determine admin-level visibility (CAO is hidden from non-admin view, which means it appears in the filtered list for admin-level users). An attacker can create a `claude_local` adapter type agent, then PATCH `metadata: { isCAO: true }`. This agent now:

1. Is filtered **out** from normal tag-filtered views (the `isCao` guard in `listAgentsFiltered`), making it invisible to regular users — effectively a hidden agent.
2. Is found by any code doing `allAgents.find(a => metadata.isCAO === true)` — including `cao-watchdog.ts` and `user-widgets.ts` — potentially triggering CAO watchdog logic on the attacker's agent.
3. The CAO is auto-assigned all tags and has `bypassTagFilter: true` on its Admin role; creating a fake-CAO agent allows it to receive watchdog notifications about any failure in the company.

Note: the hierarchy check in role creation only checks `hierarchyLevel < actorRole.hierarchyLevel`. A user with `ROLES_MANAGE` at hierarchyLevel=100 can also set `bypassTagFilter: true` on a newly created role (there is no guard preventing non-admin users from setting `bypassTagFilter: true` when creating a role — the only guard is `if (!actorRole.bypassTagFilter)` which prevents creating roles *above their level* but does NOT prevent setting `bypassTagFilter: true` on a role at the same level). This is a separate privilege escalation path.

## Impact

- An attacker with `AGENTS_CONFIGURE` (a non-admin permission) can:
  - Create a ghost agent invisible to tag-filtered users
  - Impersonate CAO in watchdog flows
  - Potentially intercept failure notifications
- An attacker with `ROLES_MANAGE` at hierarchyLevel=100 can create a role at level 100 with `bypassTagFilter: true`, assign it to themselves, and gain full cross-tag visibility

## Reproduction (creative PoC)

```bash
# Step 1: Create a claude_local agent (requires AGENTS_CREATE)
POST /api/companies/{companyId}/agents
{ "name": "ghost", "adapterType": "claude_local" }
→ agentId = "evil-agent-id"

# Step 2: Patch metadata to appear as CAO (requires AGENTS_CONFIGURE)
PATCH /api/companies/{companyId}/agents/{agentId}
{ "metadata": { "isCAO": true } }

# Step 3: The agent is now hidden from non-admin users and participates in
# CAO watchdog flows — a backdoor in plain sight
```

For the `bypassTagFilter` escalation:
```bash
POST /api/companies/{companyId}/roles
{
  "name": "superuser", "slug": "superuser",
  "hierarchyLevel": 100,
  "bypassTagFilter": true,
  "permissionSlugs": ["roles:manage", "users:manage", ...]
}
# Then assign yourself this role:
PATCH /api/companies/{companyId}/members/{memberId}/role
{ "roleId": "new-role-id" }
```

## Recommendation

1. Strip protected metadata keys before the DB write in `PATCH /agents/:id`:
```typescript
if (patchData.metadata && typeof patchData.metadata === 'object') {
  const meta = { ...(patchData.metadata as Record<string, unknown>) };
  delete meta.isCAO;
  patchData.metadata = meta;
}
```
2. For the role escalation: add a guard in `POST /roles` that prevents non-admin actors from setting `bypassTagFilter: true`. Only actors whose current role already has `bypassTagFilter: true` (or instance admins) should be able to create roles with that flag.
