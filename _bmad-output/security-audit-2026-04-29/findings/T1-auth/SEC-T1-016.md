## Description

RFC 7591 Dynamic Client Registration is implemented at `POST /oauth/register`. The endpoint has a rate limiter (5 requests per 60 seconds per IP) but **requires no authentication**. Any anonymous caller can register a new OAuth client and receive a `client_id` and `client_secret`.

```typescript
router.post("/oauth/register", oauthRegisterLimiter, async (req: Request, res: Response) => {
  // No session check, no authentication requirement
  const { client_name, redirect_uris, grant_types } = req.body ?? {};
  // ...
  const client = await store.registerClient(client_name, uris, grants);
  res.status(201).json({
    client_id: client.clientId,
    client_secret: client.clientSecret,
    ...
  });
```

Once a client is registered, it is permanently stored in the DB (no TTL, no cleanup for unused clients). There is no mechanism to list, deactivate, or manage registered clients. The rate limit of 5/minute per IP can be trivially circumvented with IP rotation.

The risk: a registered client can participate in the OAuth consent flow with any logged-in user. While the consent page shows the `client_name` and the user must approve, social engineering is possible if the client is named something trustworthy.

Additionally, the audit record for registration uses `companyId: "system"` and `actorId: "anonymous"` — making forensic tracking difficult.

## Impact

- Attacker registers a malicious OAuth client named "MnM Integration" or similar.
- Sends phishing URL `https://mnm.company.com/oauth/authorize?client_id=<evil>&...` to users.
- Users approve the consent, believing they're authorizing a legitimate tool.
- Attacker receives MCP access tokens with the user's permissions.

## Recommendation

- Require authentication for DCR: the caller must have a valid BetterAuth session with at least one company membership.
- Alternatively, require an `initial_access_token` (RFC 7591 §3) — a pre-issued token from an admin.
- Add a maximum per-user (or per-IP) limit on registered clients.
- Implement a client management endpoint so admins can audit and revoke registered clients.
- Add the registrant's userId to the audit event.
