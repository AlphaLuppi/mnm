## Description

The board-claim flow allows the first authenticated user to claim instance_admin ownership. The challenge consists of:
- A 24-byte random token (48 hex chars) embedded in the URL.
- A 12-byte random code (24 hex chars) passed as a query parameter.

The claim POST endpoint (`POST /board-claim/:token/claim`) has **no rate limiting**. The global API rate limiter (`apiRateLimiter` in `app.ts:233`) applies, but it is set to 500 requests per minute per `{companyId}:{actorId}`. For the board-claim endpoint, there is no `companyId` in the path, so the key degrades to `global:{actorId}`.

At 500 requests/minute, an attacker with a valid token (obtained from the startup banner URL) could attempt to brute-force the 12-byte code (24 hex chars, `16^24 ≈ 2^96` possibilities) — this is infeasible in practice for the code alone. However, the weakness here is different:

**The token AND code are printed in the startup banner and displayed in console output** (`getBoardClaimWarningUrl`). In containerized environments, container logs are often shipped to central log aggregators. An attacker with read access to logs (e.g., a developer with DevOps access who is not supposed to have instance_admin) can extract the full URL and claim ownership.

Additionally, `getChallengeStatus` returns `"invalid"` vs `"expired"` vs `"claimed"` — the GET endpoint at `/board-claim/:token` exposes this state machine, allowing an attacker to confirm a token is valid before attempting a claim.

The 24-hour TTL (`CLAIM_TTL_MS = 1000 * 60 * 60 * 24`) gives a large window for exploitation.

## Impact

- Any party with access to server startup logs (common in CI/CD, Docker log aggregators, or shared dev environments) can claim instance_admin.
- In Kubernetes/Docker environments where log scraping is standard practice, this is a real risk.

## Reproduction

1. Deploy MnM in `authenticated` mode with no existing instance_admin.
2. Observe the board-claim URL in startup logs.
3. Sign up for a user account.
4. POST to the board-claim URL with the logged token+code.
5. Receive `instance_admin` and membership in all companies.

## Recommendation

- Never print the claim token+code to stdout/logs in any format. Instead, print only a redacted URL like `http://localhost:3100/board-claim/<redacted>?code=<redacted>` and write the full URL to a local file (`~/.mnm/claim-url.txt`) with `chmod 600`.
- Add a dedicated rate limiter on the board-claim endpoint (5 attempts per 10 minutes per IP).
- Reduce the TTL from 24 hours to 30 minutes.
- Invalidate the challenge after a failed attempt (burn-on-wrong-code model).
