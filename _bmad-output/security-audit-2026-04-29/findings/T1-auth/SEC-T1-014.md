## Description

BetterAuth ships with a built-in rate limiter. It is explicitly disabled when `MNM_E2E_SEED=true` (covered separately in SEC-T1-008). In normal production operation, the BetterAuth rate limiter is active.

However, the global API rate limiter in `app.ts` is mounted on `/api` routes, but BetterAuth routes are mounted at `/api/auth/*authPath` and are handled by the BetterAuth handler **before** the `api` Router's middleware chain (see `app.ts:227–230` and `app.ts:366`). This means:

```typescript
app.all("/api/auth/*authPath", opts.betterAuthHandler);  // Line 228 — before api Router
// ...
app.use("/api", api);  // Line 366 — after BetterAuth handler
```

The `apiRateLimiter` is mounted on `api` Router (`api.use(apiRateLimiter)` at `app.ts:250`). Since BetterAuth requests are handled by `opts.betterAuthHandler` before reaching the `api` Router, **the global 500 req/min rate limiter does not apply to BetterAuth auth endpoints**.

BetterAuth's own rate limiter is the only protection. Its default limits are library-controlled and not explicitly configured in the codebase (no custom `rateLimit` config is passed except for the E2E disable).

Additionally, the sign-in endpoint accepts the `email` field in the request body for user enumeration: a 401 with "Invalid password" vs. a 404 with "User not found" can be used to enumerate valid email addresses. BetterAuth's default behavior should be verified.

## Impact

- Password brute-force attacks are limited only by BetterAuth's built-in rate limiter (library defaults, not explicitly tuned).
- If BetterAuth's default rate limit is 100 req/min per IP (typical), this allows testing ~1,400 passwords per IP per day — feasible for targeted attacks.
- User enumeration via timing or error message differences.

## Recommendation

- Mount a dedicated rate limiter on `/api/auth/sign-in/email` before the BetterAuth handler: max 10 attempts per 15 minutes per IP.
- Configure BetterAuth's rate limit explicitly:
```typescript
rateLimit: { window: 900, max: 10 } // 10 attempts per 15 min
```
- Verify BetterAuth returns consistent error messages (same response body and timing) regardless of whether the email exists or not.
- Consider adding account lockout after N failed attempts with admin-unlock capability.
