## Description

The JWT verifier accepts two additional (legacy) values beyond the current configured issuer and audience:

```typescript
// Accept both new ("mnm-agent") and legacy ("mnm") issuers during transition
if (issuer && issuer !== config.issuer && issuer !== "mnm") return null;
// Accept both new ("mnm-mcp") and legacy ("mnm-api") audiences during transition
if (audience && audience !== config.audience && audience !== "mnm-api") return null;
```

The comment says "during transition" but there is no code path, flag, or deadline that removes these fallbacks. Any token signed with `iss: "mnm"` and `aud: "mnm-api"` is permanently valid.

If older agents or MCP clients are still generating tokens with these legacy values, they should be migrated. The risk is low because the signature still must be valid — an attacker can't forge a token with legacy claims any more easily than with current claims. However, the expanded acceptance window for issuer/audience values increases the attack surface marginally (e.g., if a tool issues tokens with custom iss/aud values matching the legacy strings).

Additionally, the `iss` and `aud` checks only apply when these claims are **present** in the token. A token with no `iss` and no `aud` passes both checks silently (the conditions only reject if `issuer && issuer !== ...`). This means a token crafted without iss/aud claims is accepted with no issuer or audience validation.

## Impact

- Tokens without `iss` or `aud` claims bypass issuer/audience validation.
- Legacy issuers and audiences are permanently accepted with no expiry plan.
- Marginally increased attack surface if legacy claim values are predictable or shared.

## Recommendation

- Require `iss` and `aud` to be present in the token:
  ```typescript
  if (!issuer || (issuer !== config.issuer && issuer !== "mnm")) return null;
  if (!audience || (audience !== config.audience && audience !== "mnm-api")) return null;
  ```
- Set a deprecation date for the legacy values and add a warning log when they are used.
- After migration, remove the legacy value checks.
