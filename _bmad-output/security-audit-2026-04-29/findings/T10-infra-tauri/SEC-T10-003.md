## Description

The production Dockerfile installs bun using an unverified curl-to-bash pipe:

```dockerfile
RUN curl -fsSL https://bun.sh/install | bash
```

This pattern has several security weaknesses:

1. **Supply chain attack vector**: If `bun.sh` is compromised or a MITM occurs (despite HTTPS, MITM is possible via compromised CA or DNS hijack), arbitrary code executes as root inside the build stage.
2. **No version pinning**: The script installs the latest version at build time. This means reproducible builds are impossible and a malicious version could be introduced silently.
3. **No checksum verification**: The install script is executed directly without verifying a cryptographic hash.
4. **Executes as root**: The `curl | bash` runs during the `base` build stage before the `mnm` user is created, so it runs as `root` with full filesystem access.

The same Dockerfile also downloads Docker CLI via curl with only a version pin but no signature verification:

```dockerfile
RUN curl -fsSL https://download.docker.com/linux/static/stable/$(uname -m)/docker-27.5.1.tgz \
  | tar xz --strip-components=1 -C /usr/local/bin docker/docker
```

While the Docker CLI download pins a version, it does not verify the GPG signature of the download.

## Impact

- A compromised or MITM'd install script can backdoor the production image at build time.
- The resulting backdoored image is distributed to all production deployments.
- Since Docker image layers are cached, a one-time supply chain compromise persists until a full rebuild.

## Reproduction

1. MITM the `bun.sh` domain during a CI build (or compromise DNS).
2. Serve a modified install script that adds a reverse shell or backdoor.
3. The build succeeds normally; the compromised binary is baked into all production images.

## Recommendation

1. **Pin bun to a specific version with checksum verification**:
   ```dockerfile
   ENV BUN_VERSION=1.2.10
   RUN curl -fsSL "https://github.com/oven-sh/bun/releases/download/bun-v${BUN_VERSION}/bun-linux-x64.zip" \
       -o /tmp/bun.zip \
     && echo "<sha256sum>  /tmp/bun.zip" | sha256sum -c - \
     && unzip /tmp/bun.zip -d /tmp \
     && mv /tmp/bun-linux-x64/bun /usr/local/bin/bun \
     && rm -rf /tmp/bun.zip /tmp/bun-linux-x64
   ```
2. For the Docker CLI, verify the GPG signature from `download.docker.com`.
3. Consider using official `oven/bun` as a base image stage instead of installing manually.
