## Description

`docker-compose.quickstart.yml` is the intended entry point for new users (one-command quickstart). It only requires `BETTER_AUTH_SECRET` and leaves other critical secrets undefined:

```yaml
environment:
  BETTER_AUTH_SECRET: "${BETTER_AUTH_SECRET:?BETTER_AUTH_SECRET must be set}"
  # MNM_SECRETS_KEY — NOT present
  # MNM_MCP_JWT_SECRET — NOT present
  # MNM_AGENT_JWT_SECRET — NOT present
```

The production `docker-compose.yml` enforces `MNM_SECRETS_KEY` and `MNM_MCP_JWT_SECRET` with `:?` (fail if missing), but the quickstart file does not. This means a user following the quickstart path:
- May start the server without a proper secrets encryption key, causing secrets to be stored in a degraded/unencrypted mode.
- May start without MCP JWT secret, making all MCP-authenticated endpoints use a null/default secret.
- `MNM_AGENT_JWT_SECRET` is similarly absent — agents may authenticate with a null or randomly generated ephemeral secret that changes on restart, breaking persistent agent sessions.

## Impact

- New users deploying via quickstart get a server that appears functional but has weaker security guarantees.
- If `MNM_SECRETS_KEY` falls back to a default or null, all stored secrets (API keys, credentials) may be unencrypted or use a predictable key.
- MCP and agent JWT secrets that are not set may default to empty strings or be auto-generated ephemerally (not persisted), causing subtle auth failures that are hard to diagnose.

## Reproduction

1. Copy `docker-compose.quickstart.yml` and set only `BETTER_AUTH_SECRET`.
2. `docker compose -f docker-compose.quickstart.yml up`.
3. Check what values `MNM_SECRETS_KEY` and `MNM_MCP_JWT_SECRET` are defaulting to in the running container: `docker exec <id> env | grep MNM`.

## Recommendation

1. Add `:?` enforcement for all secrets in quickstart, or auto-generate them on first run with a clear message:
   ```yaml
   MNM_SECRETS_KEY: "${MNM_SECRETS_KEY:?MNM_SECRETS_KEY must be set (generate: openssl rand -hex 32)}"
   MNM_MCP_JWT_SECRET: "${MNM_MCP_JWT_SECRET:?MNM_MCP_JWT_SECRET must be set}"
   MNM_AGENT_JWT_SECRET: "${MNM_AGENT_JWT_SECRET:-}"
   ```
2. Add a setup script (e.g., `./scripts/gen-secrets.sh`) that generates a `.env` file with all required secrets, linked from the quickstart documentation.
3. The server's startup doctor check (`mnm doctor`) should explicitly validate that all required secrets are non-null before accepting connections.
