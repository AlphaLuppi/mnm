## Description

The production stage (`AS production`) of the Dockerfile does not include a `USER` directive. The `ENTRYPOINT` is `entrypoint.sh`, which runs as root and drops to `mnm` user via `gosu`:

```sh
exec gosu mnm node --import tsx/esm server/dist/index.js "$@"
```

This means:
1. The container process during the startup phase (before `exec gosu`) runs as **root**.
2. All the `RUN` commands in the production stage that install packages (`npm install --global tsx @anthropic-ai/claude-code@latest @openai/codex@latest opencode-ai`) and download the Docker CLI binary also run as root.
3. The comment in the Dockerfile reads: `# Non-root user so Claude Code accepts --dangerously-skip-permissions` — the user drop is specifically designed to enable the `--dangerously-skip-permissions` flag, which itself bypasses Claude Code's own permission system.

This creates a circular security problem:
- Root required to set up → drop to non-root → to then invoke Claude with full permissions bypassed.

Additionally, the entrypoint performs `usermod -aG docker mnm` at runtime, requiring root throughout the startup phase, further delaying the privilege drop.

## Impact

- Any vulnerability exploited **before** the `exec gosu` line runs gives root in the container.
- The init-time root operations (chown, usermod, groupadd) are a window of elevated privilege.
- Using `--dangerously-skip-permissions` in production Claude Code invocations means the server can invoke Claude with arbitrary filesystem/network access — this is a production anti-pattern.

## Reproduction

- Container starts as root (verify with `docker exec <id> id` in entrypoint before gosu).
- The entrypoint runs chown, groupadd, usermod as root before exec.

## Recommendation

1. Minimize root startup window: pre-create the docker group with a fixed GID in the Dockerfile and avoid runtime `groupadd`/`usermod`. Use Docker's `--group-add` at container start instead.
2. Reconsider `--dangerously-skip-permissions`: if Claude Code is being invoked server-side, use a scoped project with explicit permissions rather than bypassing all checks.
3. Add `USER mnm` at the end of the Dockerfile (after all root setup) and remove it from the entrypoint, to make the default process non-root. Use `--init` (tini) for PID 1 instead of the entrypoint if needed.
4. Set `no-new-privileges: true` in docker-compose security_opt to prevent privilege escalation post-start.
