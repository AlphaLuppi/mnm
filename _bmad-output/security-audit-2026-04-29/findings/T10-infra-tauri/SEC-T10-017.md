## Description

In `deploy-manager.ts`, when building a deployment container command for Node.js projects, a `port` variable is interpolated directly into a shell string passed to `["sh", "-c", ...]`:

```typescript
const cmd = projectType === "node"
  ? ["sh", "-c", `cd /app && (npm install --production 2>/dev/null || true) && (npm start || node index.js || node server.js || npx serve -s . -l ${port})`]
  : undefined;
```

The `port` parameter comes from the `startDeploymentContainer` function signature. If `port` is derived from user input without strict integer validation, this is a shell injection vector. Even if `port` is a number at the TypeScript level, the string interpolation into a `sh -c` command is a code smell that deserves validation confirmation.

Need to trace: where does `port` come from before reaching `startDeploymentContainer`?

Additionally, the `projectType` parameter determines which command is used. If `projectType` is user-controlled and not limited to `"node"` | `"static"`, there may be additional branches.

## Impact

- If `port` can be influenced to contain shell metacharacters (e.g., `3000; rm -rf /`), arbitrary commands execute inside the deployment container.
- Severity depends on whether `port` is strictly validated as an integer before reaching this function — needs further investigation.

## Reproduction

1. Trace `port` from the API route that triggers `startDeploymentContainer`.
2. If `port` is from a user-supplied JSON body field, attempt: `{"port": "3000; id > /tmp/pwned"}`.

## Recommendation

1. Validate `port` is a strict integer before use in shell commands:
   ```typescript
   if (!Number.isInteger(port) || port < 1 || port > 65535) throw new Error("Invalid port");
   ```
2. Use Docker's `Cmd` array format rather than `sh -c` string:
   ```typescript
   Cmd: ["npx", "serve", "-s", ".", "-l", String(port)]
   ```
3. Separate npm install from the serve command using Docker's multi-step capability.
