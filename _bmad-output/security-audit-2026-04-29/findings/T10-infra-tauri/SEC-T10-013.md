## Description

The security audit scope includes `apps/desktop/src-tauri/` (Tauri config, capabilities, IPC commands). However, this directory **does not exist** in the repository:

```
find /c/Users/andri/IdeaProjects/AlphaLuppi/mnm/apps/ → No such file or directory
find /c/Users/andri/IdeaProjects/AlphaLuppi/mnm -name "tauri.conf.json" → (empty)
find /c/Users/andri/IdeaProjects/AlphaLuppi/mnm -name "Cargo.toml" → (empty)
```

The `CLAUDE.md` project instructions and `scripts/parity/data.ts` reference a desktop app (`apps/desktop`), suggesting it either:
1. Has not yet been scaffolded in this branch.
2. Is in a separate repository.
3. Was removed or is in a git-ignored directory.

The parity tracker at `scripts/parity/data.ts` tracks desktop features, confirming the app is planned/exists conceptually. The `scripts/` directory references desktop parity, but no Tauri source is present.

## Impact

- The Tauri desktop attack surface (IPC commands, CSP, `withGlobalTauri`, filesystem scope, updater signing, shell execute allowlist) cannot be audited at this time.
- If the desktop app is in active use but in a separate repo without security review, high-severity Tauri-specific vulnerabilities (IPC injection, CSP bypass, update MITM) may be present.

## Reproduction

N/A — the directory is absent.

## Recommendation

1. Confirm whether the Tauri desktop app exists in a separate repository and if so, include it in the T10 audit scope.
2. If the app is pending development, establish security requirements before scaffolding:
   - `withGlobalTauri: false`
   - Strict `csp` (no `unsafe-inline`)
   - `allowlist` minimal (explicit per-command grants)
   - `dangerousDisableAssetCspModification: false`
   - Updater HTTPS with pubkey signature
   - No `shell.execute` without explicit allowlist
3. Track this audit gap in the security backlog.
