## Description

The production `docker-compose.yml` contains a hardcoded, trivially guessable PostgreSQL password:

```yaml
# db service
environment:
  POSTGRES_PASSWORD: mnm

# server service
environment:
  DATABASE_URL: postgres://mnm:mnm@db:5432/mnm
```

This password is:
1. Committed to version control in plaintext.
2. Identical to the username (`mnm:mnm`), violating any complexity requirement.
3. Used in `DATABASE_URL` which is also committed in plaintext — so both the credential and the connection string are in the repo.

While the db port is not exposed to the host (commented out), the server container has `DATABASE_URL` in plaintext, meaning anyone with access to `docker inspect` or the running container's env can trivially recover the credential.

Note: `docker-compose.dev.yml` uses `mnm_dev` and `docker-compose.test.yml` uses `mnm_test` — while slightly different, all three are trivially guessable and committed in plaintext.

## Impact

- Any developer or CI system with access to the repository has the database password.
- A compromised CI pipeline, a leaked git history export, or a misconfigured git host makes the DB password instantly available to attackers.
- In container environments, environment variables are accessible via `docker inspect`, process memory (`/proc/<pid>/environ`), or crash dumps.

## Reproduction

1. Clone the repository (or obtain the `docker-compose.yml`).
2. The DB password is on line 23: `POSTGRES_PASSWORD: mnm`.
3. If the container is running and reachable, connect: `psql postgres://mnm:mnm@<host>:5432/mnm`.

## Recommendation

1. Move the database password to a `.env` file (already gitignored) or use Docker secrets:
   ```yaml
   POSTGRES_PASSWORD: "${POSTGRES_PASSWORD:?POSTGRES_PASSWORD must be set}"
   DATABASE_URL: "postgres://mnm:${POSTGRES_PASSWORD}@db:5432/mnm"
   ```
2. For production deployments (dokploy), use the secrets management of the platform.
3. Rotate the password on any deployment where the current `mnm` value has been used.
4. Consider adding `docker-compose.yml` production credentials to a secrets manager (e.g., Vault, AWS Secrets Manager, Doppler).
