## Description

The `build` stage copies the entire build context:

```dockerfile
FROM base AS build
WORKDIR /app
COPY --from=deps /app /app
COPY . .
```

The `.dockerignore` file is:
```
node_modules
**/node_modules
.git
.env
.env.*
*.stackdump
_legacy
_bmad
_bmad-output
e2e
dist
**/dist
.turbo
**/.turbo
```

Files that are NOT excluded and could contain sensitive data:
- `.npmrc` — COPY'd explicitly in deps stage (line 22). If it contains registry auth tokens, they leak.
- `playwright-report/` — not excluded, could contain test output with session data.
- `test-results/` — not excluded.
- `.gitnexus/` — not excluded (contains code analysis data).
- `scripts/` — not excluded, includes `backup-db.sh`, `build-npm.sh`, `release.sh`.
- `evals/` — not excluded (could contain eval prompts with sensitive business logic).
- `skills/` — not excluded.
- `docs/` — not excluded (could contain architecture secrets, credentials in docs).
- `releases/v0.2.7.md` — release notes not excluded.
- `.idea/` — IntelliJ project files, potentially containing local paths or run configs.
- `.claude/` — CLAUDE.md, settings, worktrees — potentially contains local secrets or mission-critical instructions.

The final `production` stage does `COPY --from=build /app /app` which copies everything that was in the build stage, including all the above.

## Impact

- `.npmrc` with auth tokens baked into the production image (accessible via `docker history --no-trunc`).
- IntelliJ/IDE config files unnecessarily increase attack surface.
- If any docs file contained credentials (rare but possible), they'd be in the image.

## Reproduction

1. Run `docker build -t mnm-test .`
2. `docker run --rm mnm-test cat /app/.npmrc` — if auth tokens are present, they're accessible.
3. `docker history --no-trunc mnm-test` — ARG and ENV values from build stages may be visible.

## Recommendation

Expand `.dockerignore` to exclude:
```
.npmrc
playwright-report/
test-results/
.gitnexus/
evals/
skills/
docs/
.idea/
.vscode/
.claude/
releases/
*.md
README*
CHANGELOG*
LICENSE
```

Also, instead of `COPY . .` in the build stage, consider using explicit `COPY` directives for only what's needed to build (source packages + workspace config), similar to how `deps` stage handles manifest files.
