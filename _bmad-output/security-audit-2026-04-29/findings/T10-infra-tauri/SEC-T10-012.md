## Description

The `openclaw-smoke` webhook server has a minimal authentication check on the POST `/webhook` endpoint (via `OPENCLAW_SMOKE_AUTH` env var), but the following endpoints are **completely unauthenticated**:

```javascript
if (method === "GET" && url === "/health") {
  writeJson(res, 200, { ok: true, webhookPath, events: events.length });
}
if (method === "GET" && url === "/events") {
  writeJson(res, 200, { count: events.length, events });  // ALL events
}
if (method === "POST" && url === "/reset") {
  events.length = 0;
  writeJson(res, 200, { ok: true });  // Clears all events
}
```

The `/health` endpoint leaks the configured `webhookPath` (which might be a secret path).
The `/events` endpoint returns all stored webhook events (up to 200) with full payloads.
The `/reset` endpoint allows any caller to delete all stored events, destroying test evidence.

The server also binds to `0.0.0.0`:
```javascript
server.listen(port, "0.0.0.0", () => { ... });
```

If this smoke server is running in a CI or shared environment and the port is accessible, any network peer can read all webhook events or reset the event log.

## Impact

- Webhook event payloads (which may contain agent run data, IDs, or business logic) are readable without authentication.
- Event log can be cleared by any party to corrupt test results.
- The `webhookPath` is disclosed via `/health`, potentially enabling attackers to send fake webhook events.

## Reproduction

1. Start the smoke server: `docker build -f docker/openclaw-smoke/Dockerfile . && docker run -p 8787:8787 <image>`.
2. `curl http://localhost:8787/events` — returns all events, no auth.
3. `curl -X POST http://localhost:8787/reset` — clears event log, no auth.

## Recommendation

1. Apply the same auth check (`OPENCLAW_SMOKE_AUTH`) to `/events` and `/reset` endpoints.
2. If this is test infrastructure only, restrict port binding to loopback (`127.0.0.1`) in the Dockerfile or docker-compose.
3. Consider not disclosing `webhookPath` in the `/health` response.
