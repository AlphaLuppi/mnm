## Description

The main Dockerfile uses a floating tag for the base image:

```dockerfile
FROM node:lts-trixie-slim AS base
```

`lts-trixie-slim` is a mutable tag that points to the latest LTS Node.js release built on Debian Trixie slim. This means:

1. Two builds at different times may use different Node.js versions.
2. If the `node:lts-trixie-slim` tag is compromised (malicious push to DockerHub or a mirror), the build pulls the compromised image without any alert.
3. Builds are not reproducible — the same `Dockerfile` on different days may produce images with different security posture.

`docker/Dockerfile.agent` uses `node:20-slim` (version-pinned but not SHA-pinned) and `docker/openclaw-smoke/Dockerfile` uses `node:22-alpine`.

## Impact

- Supply chain attack: if a malicious actor compromises the `node:lts-trixie-slim` image on DockerHub between builds, the production image silently includes the malicious layer.
- CVEs fixed in newer patches may be silently introduced if the tag rolls back (unlikely but possible during registry incidents).
- Build non-reproducibility makes security scanning results inconsistent.

## Reproduction

1. Run `docker build` today and note the Node.js version in the image.
2. Run again in 30 days — may produce a different Node.js version.
3. `docker manifest inspect node:lts-trixie-slim` shows the current SHA.

## Recommendation

Pin the base image to a SHA digest:
```dockerfile
FROM node:lts-trixie-slim@sha256:<digest> AS base
```

Use a Dependabot/Renovate configuration to automatically update pinned digests with PRs.

For `Dockerfile.agent`, update `node:20-slim` → `node:22-slim` (LTS) with SHA pin.
